Costing Tool

RFQ generation, ingestion, and reporting for a large-scale supply chain workflow.

FastAPI · PostgreSQL · Snowflake · AWSData normalization · security · APIs
Overview

The costing platform turns multi-source supply chain data into RFQs, vendor quotations, and business reports. Its APIs needed to serve large datasets while remaining compatible with legacy ingestion schemas.

Decisions I owned +

I designed the layered Router → Controller → Service → Data Model structure and shipped CRUD backends for five dataset domains with pagination, filtering, sorting, audit logging, and upsert semantics.

I also maintained Snowflake-to-PostgreSQL ingestion, added Azure AD OAuth2 / JWT validation, and removed redundant payloads from a key RFQ endpoint.

Technical shape +

The system normalized legacy and modern schemas before writing to PostgreSQL, then generated costing and duty calculations through scheduled workflows. Protected admin APIs used MSAL/Azure AD with validated JWT claims.

Outcome +

Dataset administration became more usable at scale, and the RFQ endpoint gained roughly one second through a smaller response payload.
